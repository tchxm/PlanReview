# Backend hardening audit

Baseline: `58e3aaa` (Phase 1 + Phase 2 merged; 93 backend tests passing with real Terraform and Cedar). Every item below was checked against the code at that commit. Each weakness was found still present unless noted.

Trust model used throughout: a **local, single-user** application. The attacker we defend against is *another network client* and *a buggy or hostile browser page*, plus honest mistakes (retries, races, restarts). We do **not** claim protection against a compromised host or another process running as the same OS user, which can read the SQLite file, the token file and the Terraform workspaces.

## Weaknesses

| # | Weakness | Code responsible | Impact | Complete fix | Test | Must not regress |
|---|---|---|---|---|---|---|
| W1 | **No authentication.** Any local process or page that can reach 127.0.0.1:8000 can read all tasks and mutate them. Only a Host allow-list and an Origin check on browser mutations exist. | `engine/api.py` (`TrustedHostMiddleware`, `local_origin`; no auth dependency) | Any local caller can create tasks, confirm contracts, resolve REVIEW and call apply. Origin checks do not stop non-browser clients (curl has no Origin). | Signed, expiring bearer tokens with scopes (`read`, `write`, `evidence`) from a server secret held outside the repo; every route except `/api/health` requires a valid token; keep loopback and Origin checks. | missing / malformed / bad signature / expired / wrong-scope tokens on every endpoint; token never in responses or logs | existing API behaviour with a valid token; `/api/health` public |
| W2 | **Raw exception text in responses; wrong HTTP statuses.** `ValueError` becomes `409 str(exc)` for everything, including "Task not found" and invalid input; `OSError` becomes `503`; Terraform failures return `stdout+stderr` verbatim. | `engine/api.py:call`, `engine/pipeline.py` (`raise ValueError(...)`, `command()`), `engine/storage.py:get` | Wrong semantics for clients; leaks absolute paths, provider messages and possibly sensitive plan text. | Typed error hierarchy with stable codes: 404 missing, 422 invalid, 409 conflict, 502/503 dependency; sanitized messages; details logged server side with a request id. | contract test per endpoint and per error family; leak assertions (no paths, no tokens) | structured Phase 1 codes (`UNSUPPORTED_OPERATION`, `AMBIGUOUS_REQUEST`, `MODEL_UNAVAILABLE`); 409 for real state conflicts |
| W3 | **Sensitive data in normal responses.** Task objects include `workspace`, `plan_path`, `raw_path`, full `plan_stdout`; the audit `plan` event embeds the full raw plan JSON and `agent_edits` embeds the Terraform text. | `engine/pipeline.py:plan` (`run` dict), `Store.audit`, `GET /api/tasks*` | Absolute filesystem layout and raw Terraform output are exposed to any reader. | API views strip paths and stdout and return summaries; raw evidence stays in SQLite/workspaces and is served only by an `evidence`-scoped endpoint; error and log paths scrubbed. | exposure tests on every task-returning endpoint and audit; raw endpoint needs scope | tests and gate that read raw run data internally |
| W4 | **Global mutation lock; long work inside requests.** One process-wide `RLock` serializes all mutations; `terraform plan` (≤180 s per command) and Ollama calls run synchronously inside a request. Read-modify-write on tasks is not otherwise protected. | `engine/pipeline.py:LOCK`, `engine/api.py:call`, `Pipeline.command`, `engine/agent.py` | One slow task blocks all tasks; a browser timeout does not stop the work (no cancellation); retries can duplicate tasks or plans. | Per-task locks for mutations; durable job table with state, progress, cancellation that terminates the process tree; idempotency keys. | concurrent conflicting operations on one task; independent tasks proceed in parallel; cancel kills terraform | confirmed contract, plan/policy hash, resolution integrity |
| W5 | **Ollama host and model hardcoded; single unproven failure path.** | `engine/agent.py` (`OLLAMA_HOST`, `OLLAMA_MODEL`); outage covered only by a mocked test | Cannot point at another server; outage/timeouts not proven against a real dead port. | Environment-configurable host/model/timeouts; tests against a real closed port, a fake server returning malformed JSON, missing model, slow reply; deterministic name allowlist for canonical addresses. | real-socket tests; allowlist unit tests incl. ambiguous names | never fall back to replay; validator unchanged |
| W6 | **Audit log is an ordinary table.** Events can be modified, deleted or reordered by anyone with the file; the confirmed-contract digest is an *unkeyed* SHA-256 stored next to the data it protects, so an attacker who can write the DB can recompute it. | `engine/storage.py` (`events`), `engine/pipeline.py:contract_digest` | Tampering is undetectable in the audit; the contract hash detects accidental edits, not a deliberate rewriter. | Hash-chained events (each row commits to the previous), keyed with a secret held outside the DB, plus a verification endpoint and an external anchor file; wording that separates detection from resistance. | deliberate edit, delete, reorder, truncate | append-only behaviour; existing audit reads |
| W7 | **Platform behaviour untested** off Windows; process termination, path separators and `terraform` invocation assumptions. | `Pipeline.command`, workspace handling | Unknown behaviour on Linux/macOS. | CI matrix or documented manual matrix; termination tests. | run suite per platform | Windows results |
| W8 | **Only two operations supported.** | `engine/intent`, `engine/agent`, Cedar policies | Limited usefulness. | Per-operation schema, validation, fixtures, Cedar coverage, adversarial tests. | per-operation tests | scope of existing operations |
| W9 | **Real emulator apply unproven.** Docker/emulator path unavailable in the last run. | `engine/gate.py` | Gate proven with local resources only. | Run against an isolated emulator once Docker exists. | permitted change applies, prohibited change never starts apply | AWS apply disabled by default |

## Items verified as already good (do not regress)

- Confirmed-contract integrity digest checked before every stage (`assert_contract_integrity`).
- Plan and raw-plan hash checks; policy hash re-check in `apply`.
- `EVALUATION_ERROR` cannot be approved or waved through (`Pipeline.resolve`, `gate_reason`).
- A new plan clears resolutions; DENY cannot be approved; apply is blocked without an evaluation.
- Capability registry rejects unsupported and ambiguous requests; live mode never falls back to replay.
- Canonicalizer already masks sensitive values as `[sensitive]`.

## Ordering of work

M1 security and API correctness (W1–W3) → M2 reliability (W4, W5) → M3 audit and portability (W6, W7) → capability (W8) and emulator (W9) only if the environment allows. Status of each item is reported in the final report and in `docs/backend-hardening-status.md`.
