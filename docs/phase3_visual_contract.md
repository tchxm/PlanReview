Sources of truth: `design/planbound-site.html` (the approved full-site prototype, unchanged), `design/planbound/*` modules, the attached `planbound_globe_scroll_editorial.html`, the master prompt and Part 2 prompt, and the CRT-head robot reference image.
Evidence: the original was run in real Chrome (Playwright, GPU-accelerated) at 1440×900 and captured at boot, hero, descent, tree and robot studio; the ported frontend was captured with the same script for side-by-side comparison. Screenshots live outside the repository (session scratchpad); see the final report.

## 2. What is preserved by construction

The engine modules under `web/src/planbound/engine/` are generated by `tools/port_planbound_engine.py` from the running scripts of `design/planbound-site.html`. Bodies are unchanged except two marked `// PORT:` hooks that let the render loop stop after disposal. They run on **three r128 from npm**, so materials, colour management and bloom match the original. Nothing in `design/` was modified.

## 3. What is deliberately NOT carried over (real backend is the authority)

- `site-engine.js` sample rules, sample plans A/B/C, browser-generated 12-character contract hashes, simulated apply, session evidence, pasted-plan JSON: **not present** in the product.
- The cinematic tree's station metrics (`3 changes`, `1 review open`) were sample numbers; they are replaced with true workflow statements.
- The static Home demo Plan Review (S3/SG/IAM) is replaced by the newest real evaluated plan (or an honest empty state). The Home JSON record is filled from the backend.
- Home counters (`PLANS EVALUATED`, `CHANGES GATED`, `HUMAN DECISIONS`) are computed from real tasks. The four signal tiles stay as the original illustrations and are captioned `ILLUSTRATIVE`.

## 4. Original components that are unfinished (verified in the screenshots)

1. **Tree readability.** It is one thin luminous line with cards; the branching structure barely reads in the dark network and there is no visible canopy or leaves. It cannot yet represent an arbitrary number of real resource changes: it has exactly three semantic leaf slots.
2. **Reviewer body.** The CRT head is well-formed but the torso is a lumpy lathe blob with a checker texture rather than a ribbed turtleneck with shoulder stumps; no visible neck bracket, hex connectors or jack plugs; cables are long thin lines; the bust crops at the viewport edge; screen text is very small.
3. **Reviewer states.** Only track/idle/curious/ack/verdict glyphs exist. Task-stage states (preparing, inspecting, waiting for human, blocked, fault) are not modelled.
4. **Pages.** Contract, Plan Review, Evidence, How it works, About and Legal run on the sample engine.
5. **Cursor/label details.** The `LOOK` label is partly clipped against the nav on the studio view.

## 5. Acceptance for Checkpoint A (faithful foundation)

- Side-by-side captures of hero, descent (p .1–.95), tree and studio match the original.
- One hero and one robot renderer; route changes create no extra canvases, frame callbacks or hero re-inits.
- Reduced-motion and no-WebGL paths are readable.
- Boot, globe, tree and studio code are the original code.
